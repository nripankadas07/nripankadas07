## cookie-scope-witness

**User:** Web developers debugging which cookie reaches a route. **Task:** Same cookie names at several domains and paths obscure why a request sees different state.

Explain host-only/domain, slash-boundary path and secure eligibility for each supplied cookie and request. **Limits:** Only already-normalized cookie records: no Set-Cookie parsing, public suffix list, SameSite, expiry, partitioning, prefix acceptance, IDNA or browser conformance. IDs must not contain cookie values. URLs and domains remain visible in local output.

## dns-serial-quorum

**User:** DNS operators reviewing a zone rollout across authoritative servers. **Task:** Ordinary numeric comparison mishandles SOA serial rollover, while a partial rollout can look complete.

Classify equal, ahead, behind, half-range ambiguous and unavailable observations; calculate an explicit equality quorum. **Limits:** No live DNS queries, DNSSEC verification, TTL or propagation-time inference. Input is a single manually supplied authoritative-server snapshot. Server labels are asserted unique, not verified identities. RFC 1982 half-range ordering is undefined; ahead does not count as expected equality.

## spdx-expression-paths

**User:** Package maintainers inspecting alternatives in a license expression. **Task:** Nested AND/OR expressions make the syntactic alternatives difficult to review without expanding them manually.

Enumerate bounded conjunction alternatives, applying AND precedence, parentheses and atomic WITH exceptions. **Limits:** SPDX-style syntax, not a validated SPDX license registry. Unknown identifiers are retained; case is preserved; deprecated IDs are not normalized. No legal interpretation, compatibility, compliance, policy selection or license-text detection. Enumeration is bounded and deliberately fails when expansion exceeds limits.

## systemd-order-audit

**User:** Linux service authors reviewing an explicit startup transaction offline. **Task:** Requires/Wants pull in units but do not order them; After/Before order units but do not pull them in.

Expand explicit pull-ins from roots, separately construct ordering edges and return one concrete cycle or deterministic topological order. **Limits:** Normalized JSON snapshot, not a unit-file parser or replacement for systemd-analyze verify. No default/implicit dependencies, drop-ins, generators, aliases, conditions, failure propagation, stop ordering or live system operations. Missing pull-ins make complete false; inactive ordering targets are explicit. Blocked includes descendants of cycles, not just cycle members.

## pcap-flow-ledger

**User:** Network support engineers needing a small offline capture accounting receipt. **Task:** A traffic trace contains payloads and many protocols when the immediate task is per-direction captured-byte totals.

Read bounded classic Ethernet/IPv4 TCP pcaps and summarize directional packet, payload, wire-byte and SYN/FIN/RST counts without outputting payload bytes. **Limits:** Classic pcap 2.4 only, Ethernet linktype 1, complete IPv4 TCP records. Non-IPv4, non-TCP and fragmented records are explicitly counted as skipped. No pcapng, VLAN dissection, reassembly, checksum validation, retransmission deduplication, timing performance analysis or splitting reused four-tuples into connections. Retransmissions count again. Output includes IPs and ports and is not anonymous. No live capture.
