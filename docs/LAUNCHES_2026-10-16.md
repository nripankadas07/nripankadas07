## bom-rollup-ledger

User and pain: Manufacturing and procurement engineers reviewing a multilevel BOM export before a material estimate. Shared subassemblies and decimal quantities make spreadsheet multiplication easy to undercount; a missing leaf price should not silently look like a complete estimate.

Acceptance: Shared diamond propagation yields 4.6 leaf units and an exact 11.5 subtotal for the synthetic two-unit root; missing prices withhold the total; cycles fail; deep chains do not require Python recursion.

The example is synthetic: The synthetic diamond requires 4.6 units of leaf L at unit cost 2.5, producing exact material cost 11.5. JSON includes each propagation contribution.

Validation: 18 behavior test methods; actual wheel install and console-command checks outside the checkout; Linux Python 3.10, 3.12 and 3.14 remote CI. [PR #1](https://github.com/nripankadas07/bom-rollup-ledger/pull/1), [research/tradeoffs](https://github.com/nripankadas07/bom-rollup-ledger/blob/e0f55ab13f50f909147a768089fbbc105f70e658/RESEARCH.md), [validation](https://github.com/nripankadas07/bom-rollup-ledger/blob/e0f55ab13f50f909147a768089fbbc105f70e658/VALIDATION.md) and [preparation record](https://github.com/nripankadas07/bom-rollup-ledger/blob/e0f55ab13f50f909147a768089fbbc105f70e658/PREPARATION.json).

Limits: Material-only arithmetic. No live supplier prices, ERP/CAD importer, inventory availability, unit conversion, scrap/yield, substitutions, labor, tax, FX or jurisdiction rules. Unreachable cycles still invalidate the supplied BOM. Unused prices are listed. A complete material total is not a purchase quote or an accounting valuation.

## sqlite-fixture-closure

User and pain: Developers reducing a local SQLite bug reproduction to selected rows and their required parents. Copying a few tables or rows naively can lose required parents, while exporting the whole source shares unrelated data and makes reproduction cumbersome.

Acceptance: Selecting synthetic invoice100 includes exactly invoice100 and account1, excludes unrelated rows, and restores into an empty matching schema with no foreign-key violations. Composite keys, SQLite parent collation, cycles and BLOB/NUL-text round trips are tested; source bytes remain unchanged.

The example is synthetic: The synthetic example selects exactly two rows: invoice100 and its required account1. The report contains INSERT SQL and root/foreign-key inclusion reasons.

Validation: 17 behavior test methods; actual wheel install and console-command checks outside the checkout; Linux Python 3.10, 3.12 and 3.14 remote CI. [PR #1](https://github.com/nripankadas07/sqlite-fixture-closure/pull/1), [research/tradeoffs](https://github.com/nripankadas07/sqlite-fixture-closure/blob/c01bdff6da64db6e5083a450849887eb23cb6c68/RESEARCH.md), [validation](https://github.com/nripankadas07/sqlite-fixture-closure/blob/c01bdff6da64db6e5083a450849887eb23cb6c68/VALIDATION.md) and [preparation record](https://github.com/nripankadas07/sqlite-fixture-closure/blob/c01bdff6da64db6e5083a450849887eb23cb6c68/PREPARATION.json).

Limits: Parent closure only, not child closure, representative sampling, anonymization or a production-database access policy. INSERT SQL requires an empty matching schema with foreign_keys=ON; schema/views/triggers/extensions are not exported or run. Output preserves source row contents and may contain sensitive data: review locally before sharing. Arbitrary UNIQUE FK targets and generated/virtual tables are intentionally unsupported. No network, source writes or remote database support.

## font-coverage-plan

User and pain: Localization engineers checking a text corpus against locally available OpenType/TrueType fonts before packaging a fallback set. A font family name does not prove nominal coverage for a corpus, and coverage union can conceal missing code points or inconsistent cmap choice.

Acceptance: Synthetic Latin/accent fonts cover ABé🙂 in a stable two-step plan; missing characters are explicit. Format4 delta/array and format12 non-BMP mappings, offsets, malformed tables and preferred unsupported encodings are tested. Two installed real TTF/OTF files match FontTools4.61.1 on65617 queried code points each.

The example is synthetic: The structural synthetic example covers four unique code points ABé🙂 using Latin then accent. The files demonstrate cmap analysis and cannot be rendered as complete fonts.

Validation: 16 behavior test methods; actual wheel install and console-command checks outside the checkout; Linux Python 3.10, 3.12 and 3.14 remote CI. [PR #1](https://github.com/nripankadas07/font-coverage-plan/pull/1), [research/tradeoffs](https://github.com/nripankadas07/font-coverage-plan/blob/e00b83b259386c3f135093f00ae0a415b65de808/RESEARCH.md), [validation](https://github.com/nripankadas07/font-coverage-plan/blob/e00b83b259386c3f135093f00ae0a415b65de808/VALIDATION.md) and [preparation record](https://github.com/nripankadas07/font-coverage-plan/blob/e00b83b259386c3f135093f00ae0a415b65de808/PREPARATION.json).

Limits: Nominal cmap mapping only. No shaping, ligature/variation-selector handling, glyph appearance/outline validation, font licensing advice, optimal set-cover claim, WOFF/WOFF2/TTC support or font modification. A mapped glyph may still render poorly or be blank. Synthetic example files contain only structural cmap/maxp data, no outlines; they are not renderable fonts. Real-font mapping checks against FontTools cover only two installed fonts and stated code points.

## gpx-dwell-report

User and pain: Outdoor-track analysts reviewing apparent stops and capture gaps before summarizing a GPX activity. A long interval between nearby points can be a sampling gap rather than a recorded stop, and slow GPS drift or jumps can distort moving/stopped summaries.

Acceptance: Synthetic three-point stationary run yields120 seconds, then ends before a moving point. Segments, gaps and speed jumps cannot manufacture a joined stop. Slow drift, dateline crossing, prefixes, timezone equivalence and malformed XML/times/coordinates are tested.

The example is synthetic: The synthetic equatorial example contains one120-second anchored dwell window and no gap/speed findings. It uses invented coordinates, not a personal track.

Validation: 18 behavior test methods; actual wheel install and console-command checks outside the checkout; Linux Python 3.10, 3.12 and 3.14 remote CI. [PR #1](https://github.com/nripankadas07/gpx-dwell-report/pull/1), [research/tradeoffs](https://github.com/nripankadas07/gpx-dwell-report/blob/ecc29385b74f3bf547fb2e6d5337dcef77425f29/RESEARCH.md), [validation](https://github.com/nripankadas07/gpx-dwell-report/blob/ecc29385b74f3bf547fb2e6d5337dcef77425f29/VALIDATION.md) and [preparation record](https://github.com/nripankadas07/gpx-dwell-report/blob/ecc29385b74f3bf547fb2e6d5337dcef77425f29/PREPARATION.json).

Limits: An anchored heuristic over captured points, not proof of physical stops, true moving time, GPS accuracy or navigational safety. No interpolation, geodesic ellipsoid, map matching, elevation, GPX1.0/FIT/TCX importer or editing. Rejected jumps are reported, not corrected or deleted. Output includes supplied coordinates, so review locally before sharing. No coordinates or files are sent to a service.

## capacity-cut-report

User and pain: Operations engineers checking aggregate pool-to-task capacity compatibility in a single planning period. Total capacity can equal total demand while eligibility restrictions still leave demand unmet; an allocation alone does not explain the unavoidable bottleneck.

Acceptance: Synthetic capacity8/demand8 with restricted compatibility fulfills6, leaves2 idle and2 unmet, and a cut of capacity6. Reverse residual rerouting and100 seeded two-pool/two-task networks match independently enumerated cut minima.

The example is synthetic: The synthetic example intentionally exits1: fulfilled6, shortfall2 and idle2 despite total capacity8. Cut capacity6 equals maximum flow; this exposes the compatibility bottleneck.

Validation: 13 behavior test methods; actual wheel install and console-command checks outside the checkout; Linux Python 3.10, 3.12 and 3.14 remote CI. [PR #1](https://github.com/nripankadas07/capacity-cut-report/pull/1), [research/tradeoffs](https://github.com/nripankadas07/capacity-cut-report/blob/13fc7e7d13c2ed9832ed64ccc57e8247d7f44c9c/RESEARCH.md), [validation](https://github.com/nripankadas07/capacity-cut-report/blob/13fc7e7d13c2ed9832ed64ccc57e8247d7f44c9c/VALIDATION.md) and [preparation record](https://github.com/nripankadas07/capacity-cut-report/blob/13fc7e7d13c2ed9832ed64ccc57e8247d7f44c9c/PREPARATION.json).

Limits: Fungible integer units in one static period only. No dates, shifts, costs, preferences, indivisible jobs, individual employee assignment, fairness or optimization beyond maximum feasible units. Minimum cuts/allocations can be nonunique; input-order stability does not make an allocation uniquely correct. Compatibility and capacity are caller supplied. The certificate proves only the stated mathematical model.
